# 文档维护

以下改动在同一变更中同步更新文档：术语进 `GLOSSARY.md`，决策进 `docs/adr/`，公共契约进 `docs/contracts/`，`README.md` 同步受影响的能力摘要与入口。

- 公共 CLI 或配置 Contract。
- 领域不变量或受控 vocabulary。
- 持久化或 Schema 行为。
- Stage fingerprint 或版本语义。
- Calibration 行为。
- 架构决策。

有意偏离既有架构时新增 ADR，把决策写在 ADR 里而不是只留在代码中。行为偏离 `intent/draft.md` 且已获用户允许时，同步修改该文稿的相应表述。

## 信息归属

| 信息类型 | 唯一归属 | 变化方式 |
| --- | --- | --- |
| 需求规格 | `intent/draft.md` | 需求变化时原地改写 |
| 决策 | `docs/adr/` | 接受后冻结，由新 ADR 补充或取代 |
| 现状契约 | `docs/contracts/` | 随实现原地改写，现在时 |
| 能力摘要与入口 | `README.md` | 随当前可用能力更新，详细规则链接到所属 Contract |
| 计划与状态 | `docs/roadmap.md` + GitHub 原生关系 | 模块级路线图、票级原生任务图 |
| 证据 | `docs/verification/`、`verification-runs/` | 按次冻结 |
| 过程叙述 | issue 评论、PR、`intent/review/` | 一次性 |
| 术语 | `GLOSSARY.md` | 随含义变化 |


**规格规则**：

- 只陈述 V1 目标与判据。
- 需求变化时原地改写为新要求，行内注明出处，例如「（ADR-0035）」或裁决 issue 链接；裁决出处可以保留，交付状态不可以保留。
- 不追加日期日志，不写交付状态，也不写「不表示已交付」类句子。
- 章节号与标题文字保持稳定；新增内容不引起重编号。

**ADR 规则**：

- 沿用 ADR-FORMAT 的三个门槛：难以逆转、没有上下文会让人意外、确实经过权衡。
- 一条 ADR 记录一个决策的背景、决定和代价。
- 接受后正文冻结，只允许改状态行与错别字。[#113](https://github.com/MeteoBoy4/PaperRadar/issues/113) 的一次性整理完成后，这条规则才开始生效。
- 补充、收窄或取代决策 → 新开 ADR，旧 ADR 在状态行加反向指针。
- 正文不写实现进度与排期。决策确需约束阶段边界时，用规格 §11 定义的阶段字母或能力／闸门来表述。
- 出处写在状态行。

**Contract 规则**：

- 只用现在时描述已实现的公共边界；目标行为写在规格里。
- 每项行为的详细规则只在所属 Contract 定义；其他文档保留必要摘要与链接。组合契约定义跨组件前置与组合保证，组件规则链接到各自契约。
- 行为变化时原地修正既有说明，并检索其他现状描述，更新受影响的摘要或将重复规则改为链接；不以文末追加新说明代替修正旧陈述。
- 新建 Contract 采用固定骨架：用途与范围 → 规则 → 错误与拒绝 → 不提供／不证明 → 相关。
- 不写逐票交付叙述；出处写在「相关」小节的依据行。
- 「不提供 X」只陈述事实，补齐责任链接到路线图节点。
- 新的覆盖或验收台账放在 `docs/verification/`。

**README 规则**：

- 作为当前可用能力的摘要与导航，提供必要的命令用法和示例，详细行为链接到所属 Contract。
- 具体前置条件、数据库 head 等持久化版本由所属 Contract 维护，验收结论链接到证据；README 不另维护这些事实的副本。
- 进度、计划与后续责任链接到路线图。

**证据与过程叙述规则**：

- 证据按次冻结于 `docs/verification/` 和 `verification-runs/`。
- 票的实施过程、审阅发现留在 issue 评论、PR 与 `intent/review/`，不进入长期文档。

**变更协议**：一次裁决或实现落地时，在同一变更内依次检查：

1. 是否达到 ADR 门槛；
2. 规格中受影响的要求是否已原地改写；
3. 公共边界是否已经实现并发生了变化——只有这种情况才改 Contract 或 README；核对所属 Contract 的正文及既有摘要、引用是否一致；
4. 路线图的依赖、状态、待裁决、待探索与承接责任是否已更新。

**冲突判别**：

- 问「目标」，以规格 + ADR 为准；
- 问「现状」，以代码 + Contract 为准；
- 问「下一步」，以路线图 + GitHub 原生关系为准。

真正矛盾时沿用 AGENTS.md：保持已有安全行为，报告，并由用户裁决。
