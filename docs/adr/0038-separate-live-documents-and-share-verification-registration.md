# 分离活文档与冻结依据，并集中共享验收登记

状态：已接受；依据：[#126](https://github.com/MeteoBoy4/PaperRadar/issues/126)、[S1–S8 最终裁决](https://github.com/MeteoBoy4/PaperRadar/issues/126#issuecomment-6536667331)。

现状 Contract 随实现原地改写，而历史组整文件固定这些文档会把当前维护与历史证明耦合；共享源码重复登记和 scope 互相哈希又使并行工作在收口集中争用。采用两步边界：先分离活文档与冻结验收依据并独立验收，再以该稳定基线集中共享登记、取消 scope 字节级联。保留全部现状 Contract 绑定或将 A10 作为例外都会使日常文档修改继续承担重绑成本，因此不采用。

分类依据是信息归属与实际用途，精确路径由唯一规范数据声明，未知文档不能自动豁免。规格、README、GLOSSARY 和现状 Contract 解除整文件绑定；history、需求/覆盖台账、必要的最小冻结摘录、ADR、Schema、代码、测试、fixture 与依赖身份继续固定。A10 迁移保持 693 个需求 ID 和 37 份来源原文及 SHA，修订覆盖口径、逐项披露处置差，固定集合外指针仍拒绝。冻结测试只做已裁决的等量替换并逐项留痕，分母不减。

共享文件采用单处中央哈希，各组保留显式成员与固定计数。scope 与中央登记不进入各组逐文件哈希闭包，由结构审计、显式影响图、同次检查和完整工作树身份保护。source/support 机械变化不逐组确认；测试/计数、fixture/负例、需求/覆盖台账与格式、仍绑定契约/证据的变化，要求每个受影响组显式确认。分类控制数据的新增或改类也须显式审阅。只读分析按明确有效基线给出候选与影响，不能代替授权登记或正式结论。

新组注册采用独立维护的测试预期产物清单，状态读者独立声明支持格式；历史组测试不从生产注册表推导预期。这里只决定机制，新增能力是否转 required 与完整 A 结论仍由 A 真正收口决定。Alembic head 保持串行，字面量集中另行评估；不扩张业务语义、Stage fingerprint、Frozen Contract 版本或 migration。

代价是一次受控迁移与分阶段验收，并行工作仍需语义集成。单 spec 子票记录预期漂移，由收口统一审阅；跨 spec 后合入者必须在合并树重算登记与验证。活文档仍参与完整工作树身份，历史 status/reason 与 JSON 不重写，当前 applicability 单独计算。门禁只代表精确最终提交与材料；新增 merge commit 或改材料后需重新取得结论，main 可用保持提交身份的方式承接。所有离线事实均不替代 live、模型质量、校准或完整阶段 A。
