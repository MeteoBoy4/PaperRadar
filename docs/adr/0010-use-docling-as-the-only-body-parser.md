# 用 Docling 作为唯一通用正文解析器

PaperRadar 第一版只使用锁定版本和模型制品的 Docling 生成供 Read Agent 使用的通用正文提取物，不保留 PyMuPDF 或 PyMuPDF4LLM 运行时兜底。正文链采用精简的本地 PDF 依赖组合，运行时关闭 OCR、公式增强、远程插件和图片增强，串行处理论文；扫描稿留待第二版，GROBID 继续只在参考文献列表不可用或存在高风险缺口时运行，不作为第二种正文解析器。原 PDF 之外还保存解析清单、原始 DoclingDocument JSON、规范阅读文本及从规范块到原 PDF 页码、边界框和字符区间的证据映射。公式只保存定位占位符，表格结构可以用于语义理解，但未经人工复核的精确数值和科学符号不得成为关键证据。

单一正文制品契约减少了两套章节、页码和坐标语义造成的分叉，也使项目可以保留 MIT 授权而不承担 PyMuPDF 带来的 AGPL 发布约束；代价是 Docling 的模型、依赖、内存和首次安装成本更高。代表样本在 CPU 上约耗时 18–51 秒、峰值内存约 2.5–4.6 GB，在每天最多三篇且一周内完成精读的约束下可以接受。该选择仍受正文提取质量门槛约束：如果四刊代表性样本不通过，第一版必须重新审议解析器，而不能绕过门槛调用 Read Agent。
