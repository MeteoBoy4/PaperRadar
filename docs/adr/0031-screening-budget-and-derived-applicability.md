# 以 Paper 阶段输入承载预算，并派生筛选制品当前适用性

状态：已接受；依据 [#76 用户 D1–D4 裁决](https://github.com/MeteoBoy4/PaperRadar/issues/76#issuecomment-6356409213)，任务运行能力待 #78–#84 实现。预算与筛选制品的主体固定为同库 `(paper_id, stage, fingerprint)`，不同 Paper 不共享业务结果或次数，日期、版本 ID、请求来源、代际与配置标签都不进入 A5 语义载荷。这样输入回摆会回到既有预算；代价是将来论文合并必须另外决定预算合并，不能直接跨 Paper 复用。

当前适用性完全由明确历史 snapshot 下当前论文输入的指纹与筛选制品指纹比较派生。同指纹跨版本直接适用，缺项或指纹不同只保留历史；没有结果使用依据表、再绑定写入或提交事务中的当前论文复核。这取代 #76 原故事 29/31、决策 15–16 及缓存重新绑定测试，并按用户裁决同步主方案 §8.5，消解其旧字面读法与 §3.4/4.4 的张力；请求自己的 version/revision/snapshot 与命中回执足以保留使用审计。

D1 将原题名语言严格 bool 冻结于预算范围，不进 A5 指纹，retry 继承且不能更正；代价是误标暂无法纠正，真实 value 任务前必须另行裁决生产来源。D3 在原权威验证器拒绝任意层重复键及非有限 JSON 常量，保持单一 Schema 和业务接收权威。D4 推迟 CLI 和 paper trace 组合，仅保留服务层查询/retry 的交付目标，使未来生产调度决定实际产品交互。具体规则与未交付边界见[任务 Contract](../contracts/screening-tasks.md)。
