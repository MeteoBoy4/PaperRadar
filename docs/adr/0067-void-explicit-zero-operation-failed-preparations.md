# 显式作废零操作失败准备并回滚至已知无策略基线

状态：工程实施决定草案；依据：[#184](https://github.com/MeteoBoy4/PaperRadar/issues/184) 所有者诊断后授权同时作废两次零操作失败准备、保全历史并从干净基线重封；补充 [ADR-0065](0065-retire-authenticated-failed-placement-preparation.md) 与 [ADR-0066](0066-recover-preparing-placement-across-source-payloads.md)。新增实现和封印字节仍须所有者审阅并亲自部署。

一次退役准备及其唯一单跳接续都可在无秘密预检失败后留下 preparing；两者共用策略而主部署尚未变化。再次递归接续会延长特殊恢复链，删除日志或重写旧 marker 又会丢失失败归属。因此只为所有者明确选择的这两份 preparing 来源提供新版本作废协议；原退役和单跳恢复协议、旧封印、原日志、旧 removed marker 与快照都保留原语义和字节。

新封印绑定顺序固定的两个 payload、manifest、原日志摘要、共享策略完整身份、原 preparing marker、新策略身份及原主部署与 epoch 连续性。root 重读固定受保护来源，重新认证原有限谱系、主部署和资源、窗口、owner 输入、累计零认证／网络／模型、40/40 剩余额度、停止边界、实际空闲及选定候选没有计划／epoch／接收／激活证据。原四份历史回执可以保留，候选纯站点或负对照证据也不能按“零模型调用”混入作废范围。未知来源、任意递归、混合策略或未提交文件继续拒绝。

原两日志与共享 marker 先以原字节不可覆盖归档，再持久化绑定后继候选的作废意图，最后有界移除已认证共享策略并回读不存在。基线是原主部署完整且没有放置策略；不是恢复已经 removed 的更早策略。候选加载前先完成可只读前置报告；仅因候选策略尚未加载而不可执行的 native 检查可以待事务应用后完成。候选加载、完整预检或回读失败，先持久化回滚意图，再只移除本事务拥有的完整或已知部分策略并回读不存在；失败留下 rollback_failed，不声称干净或安装成功。断电后必须显式恢复，重认证原归档与来源后按有限阶段回滚再重试，不清理未知 `.new`。

代价是新增永久保留的作废记录和可恢复事务阶段。策略准备成功之后，主部署替换仍沿原安装日志与恢复协议；该边界之后的业务安装失败不伪装成策略已回滚。原 epoch、72 小时目标、窗口、额度、停止／撤销、历史回执及资格规则不重置，归档、作废和预检不产生执行证据。它不开放已经部署 placement 的通用策略升级或任意历史清理。
