# 用按需快照刷新当前观察并区分失败等级

状态：Proposed；依据：[#177 最终裁决 E-4、E-7、S-1、S-10](https://github.com/MeteoBoy4/PaperRadar/issues/177#issuecomment-6768256547) 与 [#181 候选发布及重启澄清](https://github.com/MeteoBoy4/PaperRadar/issues/181#issuecomment-6768786581)；补充 [ADR-0056](0056-protect-pending-revocations-with-an-append-only-log.md)。仅记录既定观察边界，不扩展部署或所有者授权。

短时观察过期与受信来源丢失具有不同含义。把例行刷新的一次临时失败解释为所有能力失败，会永久撤销仍有效的证据；以新时间戳写空快照又会把不可用误作新鲜事实。observer 定义为封印运行时内观察代码及配置身份，加按需特权 nft/cgroup 快照。进程 PID、启动时间及重新启动不是新的受信来源，原观察保留并自然变旧。

固定零参数 root 入口只读固定 nft 表、受保护目标和实际 cgroup/锚定身份，核封印成员与完整保护来源。候选核验完成后才原子替换当前观察；独立受保护刷新记录先封闭读者，避免两份文件发布间的中断暴露不完整候选。临时或原因不明的观察失败保留上一成功快照及原 observed_at，追加失败依据并拒绝本次，即使上一观察尚在60秒内；不停止计划或撤销资格。真实绑定、规则、目标漂移按登记依赖持久收紧，来源失信或影响未知时保守扩围。漂移与失信先于 stale 处理；持久化未完成继续拒绝并披露待撤销，不假称收紧已完成。

首次 β 证据采集保持原严格失败、停止及不可读观察语义，例行刷新不调用完整 β 探针。新快照不产生 verified、receive、activate、原验证时点变更、续期或任何业务/采集额度消耗；成功重试不能复活已撤销资格。受保护站点上下文不承诺 MODEL_TUPLE，每格请求及模型证据仍完整精确核验，其余组件漂移不予忽略。

正式消费者准备前、准备后请求刷新，领取事务内只读复核；doctor 按需只读同一快照、刷新结果及证据投影。无需常驻 root 服务，完整会话写史继续 not_assessed。代价是新增一个封印特权入口、短时保守拒绝及部署对稳定 nft/cgroup 目标的依赖；缺失或不支持时维持阻断。部署安装、sudoers 与真实内核故障注入由后续封印包及所有者现场验收承担。
