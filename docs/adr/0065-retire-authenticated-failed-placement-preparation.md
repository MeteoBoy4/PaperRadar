# 只退役经过认证的未完成放置准备

状态：工程实施决定；依据：[#184](https://github.com/MeteoBoy4/PaperRadar/issues/184) 既有新增字节审阅与 owner 安装范围；补充 [ADR-0064](0064-authorize-userns-for-sealed-placement-entry.md)。该具体实现及新封印字节仍须所有者审阅，不把既有授权记为本实现已经审阅。

固定无秘密 true 预检的实际解析路径需要进入同一次封印的执行规则。修正规则会改变策略完整身份；如果此前加载的策略只留下 preparing 记录，直接清记录或 replace 同名 profile 会丢失归属证明，也会把已完成部署的策略升级边界一并放宽。

因此只提供明确选择原失败封印候选的待完成准备退役。新封印描述原候选、原 preparing 记录、原策略完整身份、仍安装的旧主部署与原 epoch 连续性；部署者从固定受保护地址重读全部来源，并要求旧主部署没有 placement、其业务与来源仍完整。原策略与新策略只允许固定 true 规范规则所需的 source、binary、build 变化，native、程序、安全工具与其余输入保持。原 preparing 记录先耐久保存为不可覆盖快照，有限且绑定新 payload 的退役记录先于严格移除原已知策略；新策略随后仍走原 add、完整 raw 回读和无秘密预检，成功之前不写旧业务状态。

这选择承担独立恢复记录与原失败快照的维护成本，避免清 marker、猜最新来源、替换未知策略或开放已安装 placement 的任意升版。只支持可认证的稳定阶段及已拥有的 partial kernel 中断；未提交 `.new`、缺失快照或来源、未知或混合字节继续拒绝并保全。完成后的同 SHA 重验、卸载与显式恢复沿既有新策略生命周期，不再退役原策略。原窗口、部署 UTC、额度、停止与撤销、历史回执均不重置，退役及预检不产生执行资格。
