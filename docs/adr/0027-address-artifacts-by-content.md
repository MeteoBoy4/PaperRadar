# 制品按内容寻址，阶段指纹只做登记索引

状态：决策记录（原文未单列接受状态）；日期：原文未单列；依据：[基线裁决原文](https://github.com/MeteoBoy4/PaperRadar/blob/91e5d02e199f1921ca8afd2b7bdb8f257e6264f3/docs/adr/0027-address-artifacts-by-content.md)；补充／部分取代：无另列关系；正文边界继续适用。

PaperRadar 将制品成员统一存入以原始字节 SHA-256 寻址的内容对象布局；制品本身只保存受控种类、格式版本及角色到内容对象的数据库引用，由规范清单确定身份，不保存另一份清单正文。阶段输入指纹以后只作为业务表索引指向制品身份，不命名目录，也不进入制品身份。这使相同内容可跨种类与角色共享，同时避免把存储去重误当成阶段语义缓存；代价是制品的完整成员关系必须经数据库回放校验。该决定有意替代主方案原先按 extraction/reference fingerprint 分目录的布局，ADR-0008 的阶段失效语义保持独立。

成员先以同文件系统 hard-link 不覆盖发布并持久化，再以短事务原子登记；失败最多留下未登记内容对象。A3 不删除内容对象，备份只按固定数据库副本的引用复制，因此并发新发布不会使已登记文件消失；未来引入 GC 前必须重新证明这个边界。
