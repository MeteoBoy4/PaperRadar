# 接受有界请求可观测性，以 Pi token 报告计量用量预算

状态：已接受；日期：2026-11-07；依据：[#167](https://github.com/MeteoBoy4/PaperRadar/issues/167) 所有者 H4 计数终局裁决；补充／收窄 [ADR-0026](0026-control-pi-through-a-bounded-rpc-adapter.md)、[ADR-0046](0046-consolidate-pi-readiness-under-live.md)。

固定 Pi 的一次 prompt、认证 CLI、连接和 packet 不能证明底层实际请求数；隐藏重试、预热与刷新没有完整独立计数。为了取得精确数而引入观察 loader、新启动策略或代理，会增加运行时与隐私边界的成本。接受按实际可观察来源声明请求数的近似下界及剩余 unknown 范围，不将该下界当精确请求总数、供应商账单或“没有额外请求”的证明。请求层、来源和适用窗口分别记录；不可观察项保留 unknown，不通过零值或其他层的计数补齐。

用量预算的 token 计量以 Pi 报告为权威，成本按已知单价估算并注明来源；它不是供应商独立计费测量。沿用既有口径：Pi 未提供用量或 totalTokens 为0时保留未知，不能当零消耗。Python 对 task attempt、显式派发、retry 和每日工作数量的预算仍独立计数；该决定不取消两次 attempt、每日配额、恢复不刷新预算或可见额外模型回合拒绝等约束。关闭隐含 retry、compaction、预热等既定配置要求保持，但不能把配置声明提升为隐藏请求的实测零次。

不采用新启动策略身份，不以本次取舍重跑 EXP-2，也不将 loader 原型接入产品。原型保留为离线研究材料，不登记为真实请求覆盖、不计入验收分母或充当启动身份变更依据。独立精确请求数的缺失不再作为本轮单独的准入阻断；其余现场隔离、协议完成、实际模型、权威接收和证据激活要求分别保留，已有未测项不得改写成 passed。

doctor 和后续日报必须披露隐藏重试、预热、刷新不可见，以及 Pi token 口径与实际请求/计费的差异。精确请求计数的实现与取舍由阶段 I 在无人值守/NAS 门槛重新评估，不因本次接受有限观察而自动豁免。代价是本阶段无法独立解释全部隐含请求及其开销；收益是保持已固定执行边界，并把未知与现有预算控制分开呈现。
