# 用内核只追加日志保留 helper 失败时的收紧依据

状态：已接受；日期：2026-11-09；依据：所有者对精确草案 SHA256 `b3eca670e12ea44f66e74c66725a3ad8688936775c03b5de96ef03638237dc40` 明确回复「确认」，仅授权代码／离线验证。补充 [ADR-0055](0055-separate-protected-admission-ledger-from-business-facts.md)。实际新 root 字节仍须所有者按 P-5 审阅与执行。

普通产品文件中的待撤销记录可以被同 uid 删除、截断或恢复旧副本；只读 root 账本并不能保住尚未由 helper 落账的失败。helper 不可用时，另一个普通 marker 或业务数据库也不能提供不可放宽的依据。拟增加一个独立、由 Linux 内核强制只追加的收紧日志；准入账本仍无产品写入通道。这对 D-6 的「产品零写入」增加了一个明确例外：产品只可向该日志追加拒绝事实，不能写授予、移除旧拒绝或操作 root 账本。此例外须由所有者接受后生效。

固定日志为 `/var/lib/paperradar/live-evidence-intents/pending.jsonl`。目录及完整祖先均须 root 所有，目录为 0755 且组／其他不可写；日志为 root 所有、所属组为封印配置选定的产品 gid、0660、普通单链接文件，并具有 `FS_APPEND_FL`。文件属主和父目录隔离阻止产品修改权限、删除、换链或替换，内核标志阻止截断、原位覆盖及以旧副本回滚；设置或清除该标志要求 `CAP_LINUX_IMMUTABLE`，不授予产品该能力。读取与追加均核完整路径链、fd 实际属主／类型／模式／链接数及 `FS_IOC_GETFLAGS`，拒绝符号链接、未知 ioctl ABI、不支持该能力的文件系统和属性失信，不退回用户 pending 文件。root 及等价能力、替换挂载或直接修改产品源码仍在威胁模型之外。

不可逆收紧只由实际失败事实触发：物理回执／CurrentObservation 来源丢失、来源不可信、已知执行绑定漂移，以及实际运行／模型身份失败。受信文件仍存在且完整、仅超过60秒的 `observation_stale` 是当前观察租期结束；能力自然到期、未测／unknown、未接收或未激活也是独立资格维度，只拒绝本次执行，不据此撤销无关已核站点分项或追加本格全部撤销。完整且同事实的新鲜观察可以恢复当前适用性，不刷新原 `verified_at`，也不能翻转真正已经撤销的资格。这延续已接受 D-4／ADR-0053 的站点与工程漂移有效期，不把站点证据变成60秒永久寿命。

产品不创建该日志，只以 `O_APPEND | O_NOFOLLOW` 追加封闭用途、来源／影响与时点，并在成功返回持久化前 fsync。日志只表达收紧；记录一旦存在便不由 helper、业务恢复、账本恢复、重装或卸载删除、改写或轮转。即使 helper 随后失败，共享 loader 仍按日志拒绝对应旧资格，doctor 保留「待撤销」。因来源物理丢失／失信或已知漂移而首次绑定构造失败、没有回执 ID 时，记录本格收紧及截止时点；其覆盖当时已接收的全部该格来源。helper 的固定 `revoke-use` 仅根据受保护 receipts 登记撤销该格已有回执，不读取缺失 inbox，也不接受自由路径、SQL、调用者时间、恢复或激活动作。后续新来源须经过新的受信采集／接收和所有者显式激活；重新激活同一旧回执不能清除其收紧。

日志初始化是一次所有者 cutover，不是自动补文件。部署先暂停任务与其他准入写入；在受保护账本追加恢复屏障并撤销所有 cutover 前已登记回执的六格资格，保留原回执、核验状态、原 `verified_at`、计划、失败、停止历史和业务预算。来源已经丢失时仍按受保护登记撤销，不把找不到用户 pending 文件当作「没有旧失败」。随后以独占创建生成含版本和账本 cutover 身份的首记录，设置属组／模式和内核只追加标志并持久化、复核；首次只追加保护完成前，新消费者始终拒绝。幂等重跑只核现有已完成身份，不重建、清空或自动完成未知／部分日志。任何中断保留现场并停止，由所有者核对后决定续行。旧版本 runtime 和既有部署包原字节归档保留；旧激活不能转成新日志下的干净授权。新策略版本、受信新计划和当前实际新证据到位后，再由所有者完整审阅并手动激活所需非空分项；不导入历史探索证据，不自动激活或续原时点。

日志总量上限为 8 MiB，单次规范记录上限为 16 KiB。读到损坏、残缺尾行、未知记录版本、超限或无法核验的 cutover 时整体拒绝；追加前超限也拒绝，不通过自动清理恢复可执行。I/O 或 fsync 失败返回受控错误，并尝试现有受限 helper 的受保护收紧；只有日志 fsync 或 root 事务确已成功，才能报告对应持久化成功。两者均失败时维持本次拒绝并明确持久化未完成，不能声称已有跨重启记录。空间、文件系统或属性问题交所有者修复，不能自动清空、移走旧拒绝或放宽资格。

相比新增常驻 root 服务，此方案不增加监听端点和服务生命周期，但引入 Linux 文件属性与文件系统能力依赖，并接受日志损坏／恶意追加只能造成停机、不可自动回收的代价。只用现有 helper 的方案无法覆盖 helper 失败后的同 uid 回滚；用户 marker／数据库与签名但可删除的文件同样不足。离线只能验证 fd／ioctl／文件操作边界模型和拒绝逻辑；真实 `+a`、产品 uid 的删除／截断／改写／替换拒绝、helper 失败持久性及 owner cutover／新激活，须在最终冻结新包由所有者执行后验证。未验证或不支持时继续阻断。

机制依据：[Linux man-pages 的 FS_IOC_GETFLAGS／SETFLAGS](https://man7.org/linux/man-pages/man2/FS_IOC_GETFLAGS.2const.html)、[Linux UAPI 文件标志](https://github.com/torvalds/linux/blob/master/include/uapi/linux/fs.h)、[内核打开与删除检查](https://github.com/torvalds/linux/blob/master/fs/namei.c)。这些来源说明机制，不证明部署机已经支持或完成设置。
