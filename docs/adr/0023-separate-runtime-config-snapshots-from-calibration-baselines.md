# 区分运行配置快照、阶段输入指纹和校准语义基线

PaperRadar 将所选版本化配置编译为不可变的运行配置快照（`RuntimeConfigSnapshot`），供多次运行与任务引用；它不是某次运行的执行计划，也不包含论文输入。各阶段只取与自身语义相关的配置投影，再结合该阶段实际使用的论文内容、摘录或 PDF 等输入生成阶段输入指纹；校准语义基线本身不充当所有阶段制品的缓存键。这样保留完整配置审计身份，同时避免无关配置变化误伤制品缓存（ADR-0008）。

正式校准固定引用从运行配置快照导出的校准语义基线，并另行冻结批次的用户可见输入，不是把整份快照变成可变的“冻结计划”。基线覆盖能够改变 Screening、条件式复用升级、摘录产生或筛选建议的配置；校准评价记录所依据的快照与基线。门禁比较当前基线与评价基线及其校准变更审计链：相同基线可直接沿用；发生校准相关差异时先暂停并交由用户分级，`minor` 可沿审计链继承既有门禁，`major` 必须由通过的新评价及用户再次显式启用解除。只改变 Read 模型等与校准无关的配置，可以产生新快照，但不产生校准变更，也不要求重新评价或关闭门禁（ADR-0020）。

不以完整快照 ID 相等作为门禁条件，也不为“当前 Screening RuntimePlan”建立第二个可变计划。代价是实现时必须维护稳定的阶段/校准配置投影及前后差异，并同时保存完整快照引用和评价、分级、启用事件的审计链；不能用某个哈希的变化自动替用户判定 `minor` 或 `major`。
