# 通过继承 flock 描述符保护本机安装使用

2026-10-18，依据 Issue #36 安装保护裁决与 #41。

安装使用保护由本机 Linux 内核的 flock 与 open file description 生命周期承担。
每实例的锁固定为 `<install-root>/.locks/<install_id>.lock`，位于运行树之外，
不进入 tree-v1、supply_id、阶段投影或校准基线，也永不成为清理候选。
这不是论文任务、attempt 或业务 lease；不保存 PID、过期时间或模拟持有者行。

使用方先取得共享锁，再重新读取登记与可用性、比对调用方明确快照的全部已选槽，
全量核对运行树，最后取得固定绝对 Node/npm/Pi 入口。定位锁所需的首次读取不构成
可用性证明。当前选择在领取过程中变化则受控拒绝重试；已交出的句柄保持旧入口。
verify 的真实程序调用通过 `pass_fds` 明确继承同一描述符；activate 的全树核验和
短事务发布也处于共享锁之内。SQLite 写事务中不等待实例锁。

父句柄退出或失败只 `close(fd)`，绝不显式 `LOCK_UN`。后者会解除仍由子进程持有的
同一 open file description 上的锁。父正常 close 或被 SIGKILL 后，只要子或后代仍
持继承 fd，保护就继续存在；最后持有者关闭或退出才由内核释放。多个使用方分别
open 同一锁 inode，单个使用方结束不会解除其他持有者。锁文件永不 unlink 或替换。

共享取得与 GC 排他取得都使用非阻塞 flock，竞争返回受控 busy，无无界等待。
GC 使用独立 open 的排他句柄，在持锁时重新核对登记、根归属、安全位置和实际树身份；
它允许与冻结预期不符但仍可安全定位的坏树，以便后续按计划的实际 hash 清理。
执行侧始终要求冻结预期树。瞬时探测结果不能替代执行时真实持有 EX 与再次复核。
本决策不实现退役、trash 或删除；那些动作必须继续遵守该互斥窗口。

只读 doctor 用 `O_RDONLY | O_NOFOLLOW` 打开既有锁文件，独立非阻塞探测后关闭；
不 mkdir、不 O_CREAT、不修复锁文件、不写使用记录。缺锁、链接、不安全身份、无法访问
返回 unknown 并保守保护，不能当成没有在途使用。发布路径为新实例初始化锁，执行路径可为历史缺锁实例安全初始化；只读查询从不初始化。

只支持供给契约既定本地文件系统，拒绝网络文件系统，不承诺 NFS/CIFS 锁语义。
检查根归属、路径组件、普通锁文件身份与 inode；这约束遵守公共协议的本地程序，
不构成对同用户恶意替换文件的 OS 安全隔离。恢复副本若共用原根，仍共用同一锁；
它只保护实际在途文件使用，不能识别另一个空闲副本的当前选择。旧活动副本退役前
不得执行 gc execute。真实 Python 父子管道握手及 pidfd 测试验证继承与释放，
不以固定长 sleep、裸 PID 退出或 TTL 推断可删除。
