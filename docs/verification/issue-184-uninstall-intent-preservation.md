# 卸载时保留只追加收紧日志的独立回归

依据：[所有者降范围裁决](https://github.com/MeteoBoy4/PaperRadar/issues/177#issuecomment-6814413453)、ADR-0056 的原只追加日志保护规则与 ADR-0068 的全部历史保留要求。

## 发现与修复

读取身份修复后的进一步只读元数据扫描发现，固定 `pending.jsonl` 是唯一允许产品组写入的历史文件；其设计为 root 所有、产品 gid、0660、单链接、父目录0755且内核 append-only 为真、immutable 为假。普通“不可组写”规则不适用于这个已知专用对象。未修改它的字节、权限、属主、标志或 journal。

卸载工具仅对固定日志使用其原专用元数据与只追加标志规则，仍拒绝其他可写对象。它持有该日志现存 fd 的真实排他锁，防止合作式追加跨越归档／卸载，既不创建或轮转日志，也不设置内核标志。原日志保留原位和原字节；私有备份为 root 可读写的0600字节归档，另记录原gid/mode/只追加事实与摘要，并核对备份内容。归档不成为新有效收紧日志。

## 独立 D1 登记

`tests/test_live_uninstall_intent_preservation.py`：11 项。

- 原日志 inode/权限/gid/字节保持、完整卸载及归档核对：1。
- 缺失 append-only、只有 immutable、两者同时存在均拒绝：3。
- 错误 gid、错误 mode、硬链接及其他可写文件拒绝：4。
- 真实并发排他锁、读中追加检测、仅使用读取 ioctl：各1。

首个完整卸载用例修前拒绝、修后通过；与原卸载及读取身份模块合计41项通过。新增节点独立登记，不扩大历史分母，不修改原测试、旧台账或回执。

## 限制

只读现场扫描核对了固定日志的原元数据与内核只追加标志，不读取其正文、不更改标志。离线测试使用合成日志与可替换内核标志事实，不在主机设置 append-only，也不执行 sudo 卸载。
没有 Schema／migration、产品执行或准入源码守卫变更；没有完整门禁。现场 root 专属核验与卸载后验仍由所有者本人执行。
