# #167 A6：预算持久性离线原型

新增 `scripts/issue167_budget.py`，仅操作显式指定的合成SQLite文件，没有网络、认证、Pi、调度或产品许可接口。计划身份是案例清单/分层上限的非秘密SHA，**不是所有者批准**；真实H2批准与接收权威尚未接线。前轮生命周期原型、历史余额与EXP-2证据原字节不变。

## 实际行为

- 新建账本排他创建；初始化失败保留文件，普通打开只接受已存在的文件与同一计划，缺失或不完整时不自动重建。
- 每个案例发送前用 `BEGIN IMMEDIATE` 事务永久预占整例上限；auth CLI、prompt、模型操作、refresh HTTP四类分别受总额约束。模型操作包含HTTP inference和WS response.create，不赠送另一传输的余额。
- 案例身份是冻结case ID，run ID仅关联本次执行。换run ID、重启controller或报告0用量都不能重新领取同一案例。没有退款/删除reservation/自动追加预算接口。
- 未结算的前例阻断下一例。结束必须同时有已知且未超限的独立计数和清理确认；计数未知/非法/超限或清理未确认，事务记录结算并永久blocked，重开账本仍拒绝。失败结算的拒绝异常不会回滚blocked。
- 计划对象的dict被修改时不允许预占；结算检测计划漂移也阻断。两连接共享事务与同一余额，不能各自取得一份上限。

原型统一预占整例上限，不按实际0/少请求退额度，刻意保守。取消、认证失败、未知发送结果都消耗所预占额度；若未来需要恢复一项现场案例，必须形成新明确授权并关联旧历史，不能重用或抹除旧reservation。

## 证明范围与后续要求

本原型用 `cleanup_verified=True` 表示**合成测试驱动声明**，并不验证cgroup/目录事实，也不接受它为生产清理权威。计数也由测试显式给定，不是实际HTTP测量。没有存真正token、其派生值、prompt或文件内容。

同uid攻击者删除/替换数据库、回滚快照/时钟、伪造输入或修改Python不能由此防御。普通打开缺文件不重建，仅防误重置，不代表能够阻止手动新建另一个账本。真实产品/现场控制器须使用受保护状态根、一次计划对应的稳定权威索引、所有者批准签收、日志/状态连续性和独立外部锚点；缺状态、换根、复制旧库或索引不一致均阻断。SQLite事务演示进程重启与连接竞争的逻辑，不承诺未经测量的主机掉电/磁盘损坏恢复。

当前六格+故障批次仍按[现场计划](../../intent/review/issue-167/field-plan.md)与H2逐轮批准；没有创建真实执行账本或改变历史余额。产品 `read_evidence=None` 保持。
