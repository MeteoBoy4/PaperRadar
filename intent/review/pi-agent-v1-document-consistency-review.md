# Pi 接入 V1：文档结构与语义审阅

2026-10-11。依据用户对 [可行性研究](../discussions/pi-agent-contract-feasibility.md) §5 及“我的决策”的采纳，核对 [V1 规格](../draft.md) 全文、[领域词汇](../../CONTEXT.md)、全部现有 ADR、已交付配置契约和相关权威 Schema。此次仅修改文档，研究材料保持原样；代码、配置文件、lockfile、数据库、migration 与 Frozen Contract 未修改。

## 结论

本轮发现的 Pi 接入冲突与遗漏已同步处理，未发现需要扩大 V1 能力范围才能解决的冲突。V1 首次通过 Python 控制 Pi RPC，以 `prompt_only` 取得候选制品，由 PaperRadar 权威 Pydantic Schema 与业务规则决定接收。专用提交工具保留为 §5 边界内的显式备用升级；能力可以共存，但同次运行只有一个权威通道，不自动切换。研究 §6 的模型、全文、PDF 与 evidence 工具不进入 V1。

## 已处理的冲突、遗漏与歧义

| 检查项 | 原问题 | 修改后的边界 |
| --- | --- | --- |
| 模型调用实现 | §7.6、第十章和 ADR-0004 仍选择 PydanticAI | Pi RPC adapter，新增 ADR-0026 并明确取代关系 |
| 输出协议 | 示例全部为 json_schema，允许运行中有限切格式 | 默认 prompt_only；提交工具需显式升级和配置映射，失败不切通道，不冒称 provider 原生严格 Schema |
| Schema 权威 | §4.5/§7.4 的“唯一权威”可能被理解为文稿中的示意类 | 生产权威为代码中的 Pydantic 模型与公共验证器；Pi/TypeBox/Frozen Contract 从同一权威生成；Read 临时 Schema 不取得生产资格 |
| 输入隔离 | 只描述逻辑阶段，未覆盖 Pi 会话历史 | 论文、阶段、每次 attempt、Read map 各块和 reduce 分别隔离，只消费 Python 显式输入 |
| 完成判据 | RPC ACK、进程退出和模型成功未区分 | settled、最终 stopReason、实际模型、所选通道及权威校验共同决定成功；超时/取消/异常不提交部分结果 |
| 尝试预算 | 未覆盖 harness/provider retry、compaction 与工具回合 | 关闭隐含调用；一次 attempt 最多一次模型调用，同一阶段输入最多两次，进程重建不刷新预算 |
| 指纹与校准 | 只列模型/提示词等身份，遗漏适配器行为 | 实际语义进入相应阶段指纹，Screening/reuse 部分进入校准基线；共有行为按实际影响判断，由用户分级 |
| 留存与隐私 | “原始响应全部保存”可被理解为保留失败全文或完整 session | 永久保留通过校验的权威成功输出；失败仅保留脱敏信息，完整 session/RPC/JSONL 不永久落盘 |
| 工具与权限 | 工具 allowlist 容易被误认为完整隔离 | 默认无工具，升级后仅专用提交工具；另行约束子进程权限，不开放通用工具或研究 §6 能力 |
| 实施与验收 | 接入边界未进入阶段、配置前置和故障矩阵 | 补齐阶段 A/B/D/G/I、上线前配置、doctor、备份恢复及跨阶段验收矩阵 |
| 既有细节 | 阶段一/二主题依赖未区分；PDF 失效描述漏掉贡献摘录的情形；“预热期制品可复用”易误读 | 主题只进入阶段二；PDF 已贡献摘录时影响相关升级；warmup 永久排除，缓存不恢复资格，均为既定行为澄清 |

## 结构与相邻文档核对

- 保留原十六章和既有子节编号，仅新增 §7.7；没有因接入 Pi 重排九阶段或领域流程。
- CONTEXT.md 新增模型适配器、适配器语义和权威输出通道的概念定义；RPC、Node 和配置实现细节放在规格与 ADR 中。
- ADR-0004、0008、0016、0017、0020、0022、0023 与 ADR-0026 相互一致。ADR-0010 的公式限制已有 ADR-0025 明确取代，Pi 接入不改写该决定。
- SQLite 唯一事实源、只追加历史、只读 Markdown、人工优先、盲评隔离、校准门禁和失败隔离继续成立；Pi 不形成第二套状态、持久化或流程权威。
- README 与 `docs/contracts/runtime-config.md` 记录当前交付范围，仍是当前代码契约。规格已明确区分未来 Pi 目标与当前配置就绪，保留现有协议枚举和不可变版本，不把文档更新当作实现交付。
- 研究文档中“候选”“尚未实现”和 PydanticAI 的描述是实验时点记录；当前采纳范围以本轮规格及 ADR-0026 为准，不改写研究历史。
- 本地 Markdown 链接、代码围栏配对、子节唯一性和节引用已检查；§7.6 配置示意通过当前 Models 权威模型校验，三个槽均为 prompt_only。该结构检查不证明真实 Pi 调用已经可用。

## 已明确留待实现的事项

1. Pi 运行策略的版本材料、快照与阶段投影映射，以及现有模型参数的实际支持检查；不支持的参数必须明确拒绝，不能静默忽略。现有配置完整性检查不等同于执行就绪。
2. 专用提交工具升级的受控协议名称与配置 Contract。默认 prompt_only 可先完成；升级前须同步权威 Schema、文档和必要 migration，并处理相关校准变更。
3. 子进程和扩展的实际权限约束、固定资源启动、RPC 取消与异常恢复、脱敏错误映射及用量缺失标记。不能仅靠 --tools 宣称已实现隔离。
4. 生产 Read 权威 Schema/验证器、正文与数字警告门槛、恢复幂等及四刊 fixtures。研究临时校验不替代这些验收；已暴露研究样本在正式采集时登记排除。

以上是实现及验收工作，不是新增功能授权。此次未运行新 live 调用，也未重新分类校准变更、启用提交工具或开启自动精读。
