# #167：真实 IPv4 出站的 H4 边界选择

本比较已由所有者 H4 终局选 A；现行范围见 [ADR-0050](../../../docs/adr/0050-bind-egress-to-owner-visible-addresses.md) 与 [DNS/TLS 计划 v1](real-exit-dns-tls-v1.md)。下文只保留裁决前比较，不作为当前执行或再次裁决请求。

本材料不授予 DNS/TLS/认证/模型请求、Node/Pi 执行或新的 root 变更。IPv4-only 已由所有者允许且本轮采用，不重新索取双栈裁决。v5 证明的是固定 loopback 合成组合，不证明真实出口；当前模型/刷新端点的地址、TTL、解析来源和上游路径都尚未冻结。

## 已有事实

- 固定公开源码 `pi-ai/dist/providers/openai.js` 声明 `https://api.openai.com/v1`，首批 Responses API 沿此 provider 路径；OAuth 源码声明刷新端点 `https://auth.openai.com/api/accounts/oauth/token`。这些是源码目标，不是当前解析结果或现场连接证据，不包含凭据。本轮没有解析、TLS 或 HTTP。
- [EXP-2 历史报告](../../../docs/verification/exp-2-pi-live-probe.md)明确当时所有者接受 fake-IP/透明代理上游不检查/调整；该历史现场的临时许可、地址及余额不自动用于 #167。
- 本轮普通用户宿主只读 netlink 元数据：5个 link、3条 IPv4 rule、10条 IPv4 route；所查非 main/local 路由数0、所列 tunnel-like link 数0。没有读取代理配置或任何环境。它既不能确认当前存在透明代理，也不能排除网关、重定向、上游映射或未被所列类别覆盖的转发；不能写“已证明直连”。初次工具沙箱拒绝 netlink 读取，之后同一普通用户沙箱外只读导出，未修改路由。
- 新 launcher 的子进程环境是显式构造；客户端代理形状与宿主透明路径是不同绑定。模型/认证阶段仍须分别限制精确目的地址和端口；UDP/DNS 不因选择 IPv4 自动开放。

## 两条路径的成本和证明范围

| 路径 | 后续需做的具体准备 | 可接受的证明范围与残余 | 成本 / 失败处理 |
| --- | --- | --- | --- |
| A：接受现有网络路径，允许存在未独立审计的 fake-IP/透明上游 | 另冻应用可见的 API/Auth IPv4 集、解析来源与 TTL、TLS FQDN/证书校验规则及客户端代理形状；项目 cgroup 分阶段 allow/reject，其余地址/UDP/DNS拒绝；来源/地址/TTL/绑定变化即停止 | 证明项目可见目的集合与 TLS 身份，**不声称**物理直连、独立验证上游映射或最终线路；现有宿主信任/证书环境的残余明确保留 | 不要求先改宿主转发路径，准备与回收最少；若实际地址落 fake-IP/上游路径不明，按本次明确接受的范围记录，不用“直连”标签补证 |
| B：要求项目流量具备可核验的 IPv4 直连路径 | 先确认当前真实路径及解析结果；若当前转发影响项目，再设计仅影响项目的 bypass/路由方案和具体权限/恢复，另审 H1；不能直接改全机代理/DNS或影响其他程序 | 目标是额外取得直连适用证据，当前尚无该证据，也未证明需要何种配置或现环境是否可实现 | 增加路径核查与可能的项目路由工程；需要新权限或无法保持项目范围时交 H4，不能自动增加 cap、namespace 或换通道 |

选择 A 是明确接受较窄的出口证明范围，不能由 agent 从“IPv4-only”推定；选择 B 也不意味着现在已授权网络探测或 root 配置。两条路径均不改变 core/计数终局，不允许自动 fallback、扩大地址集合或打开全部 UDP，不替代后续 H2 逐批预算。

## 裁决后的下一份具体包

先准备不带凭据的 API/Auth 端点与解析/TLS计划，列精确域名、解析方式和查询次数、TLS连接次数、绝对截止、地址/TTL冻结、停止/恢复及仅元数据回执；另申请适用 H1/H2/H3，不先发模型或认证请求。真实凭据仍由所有者供给。

本材料尚不是可执行现场包，未填地址不由旧 EXP-2 或源码域名补猜。当前只需选择上述证明边界；具体调用授权在完整、可复核的包形成后单独提交。
