# #167 H4-core：两条路径的差异化成本（比较材料）

后续终局已明确：不选路径二，暂不选路径一，转为验证项目显式零core限额的第三条路，见 [ADR-0049](../../../docs/adr/0049-bound-core-persistence-with-explicit-zero-limit.md)。下表保留比较依据，不再是待选择菜单。

原比较范围：不批准前置过滤器原型，不从本票“不长期改变其他程序core行为”推定全机core分发链豁免。本文只比较，不选方向、不制作分发器、不降低既有判据，也不授予现场、启动策略或产品许可。

事实入口：[备份/同步及上传](../../../docs/verification/issue-167-host-crash-facts.md)、[固定Node分支与Pi令牌入口](../../../docs/verification/issue-167-node-auth-facts.md)。所有“未知”都保留，当前两条路均未获准部署。

| 维度 | 路径一：不外流 + 可清理 + doctor可查 | 路径二：全机分发器 |
| --- | --- | --- |
| 接受的目标 | 必须由所有者明确是否接受短时本机core/proc采集残留；不能由agent把原有core判据改成可保留秘密。以本机不外流、可精确清理、调用前可诊断为新方案待裁决 | 在既有collector之前拒收本项目core，并保持非项目行为；涉及全机分发链，超出本票可推定范围，须单独明确范围与授权 |
| 当前事实距离 | 已知服务不活动不等于全部上传通道永久关闭；任何备份/同步范围的否定尚不能穷尽。固定Node分支须结合有效limit/Apport配置，不能默认总会或总不会写 | pre-exec dumpable充分性已否定，Apport ignore也不是最早拒收。尚无分发器代码或有效性证据，本轮不编写 |
| 宿主改动范围 | 若最终获准，限定相关项目/目录的备份同步排除、crash上传关闭、权限与清理；关闭全机上传本身也可能影响其他程序，必须具体审阅，不能自动执行 | 修改core_pattern/现有collector前置入口、根权限代码、受保护项目身份及非项目透明转发，必须覆盖所有使用该分发链的程序与故障模式 |
| 备份/同步成本 | 需要完整负责者清单、精确include/exclude及快照/历史副本处置；只证明PaperRadar backup范围不足。/var/crash、rawcore目录、collector日志/其他实际输出分别评估；外部/NAS/云备份不可查即unknown | 拒收必须发生在复制/额外proc采集前，避免新项目core进入这些根；已存在材料和collector历史仍需独立处置，不会因换分发器自动消失 |
| 清理成本 | 先停止并确认所有后代，再通过受控身份索引精确定位本项目残留；不能为了匹配而读取core/凭据，不用泛前缀删除其他程序材料。共享Python、日志轮转、rawcore命名与已有快照可能无法可靠归属；无法归属即不可宣称可清理 | 项目路径尽早关输入而不读core；非项目仍转发原fd/argv/退出语义。要证明PID复用、cgroup逃逸、collector失败、并发和安装/卸载期间行为，不只是写一个shell包装器 |
| doctor候选检查 | 只读配置/元数据：collector身份与策略、上传unit运行/启用/触发条件、备份排除清单及其覆盖来源、残留根权限/索引/清理回执。每项passed须有来源，unknown阻断；不读取crash/core/完整日志或秘密。需后续明确工程，现产品doctor无此能力 | 只读core_pattern/handler字节身份、受保护匹配规则、项目与非项目受控正负对照、恢复状态。必须另审root执行与collector完整性，doctor读几个布尔不能自证 |
| 残余风险 | 局部配置漂移、临时文件被其他同步器读取、操作系统/其他管理员快照、崩溃时清理未完成、存储删除不等于物理擦除。若目标是完全不让collector接触秘密，这条路径可能不满足，而非可由agent默认豁免 | 全机新增可信代码与失败面、错误归属或转发导致其他程序core处理变化、升级兼容及紧急恢复成本。即使正常行为相同，也不能自动称未改变其他程序行为 |
| 维护与重验 | 每次调用核对配置来源与覆盖完整性；变更/未知即阻断。清理与备份恢复演练、上传规则漂移、各类故障均需独立验收 | 持续跟随内核/collector更新；每次变更需项目和非项目对照、并发/失败/回滚演练及范围重批；不能沿用旧EXP-2证据 |
| 秘密延迟供给的关联 | Pi源码是否有非环境入口与当前CLI/RPC是否可用分别判断；即使有进程内setter，也须新接线与秘密到达前保护的证据，不能补猜这条路径已成立 | 全机分发器并不能替代认证、token传输、文件/内存隔离与请求独立计数；其存在不授权改变Pi供给接口 |
| 批准后最小下一步 | 所有者先裁定可接受残留边界与证明范围；然后形成实际排除/关闭/精确清理/doctor的差异与无秘密验证。条件未知时不进真实认证 | 所有者先另行明确是否允许全机分发链方案；之后才可能形成实现原型及非项目透明性验证计划，本轮无该许可 |

## 本轮保持的闸门

四条事实是有界只读核查，不是准入验收。“任何备份/同步”与“任何上传”如未能完整核对，必须unknown，不能以未发现当不存在。秘密延迟供给的源码可行性不等于生产CLI已支持。两条路对core判据的适用差异由所有者一次性裁决；本文不推荐或选择任一路径。

观察loader只获准安装树外的离线原型；没有采用生产启动策略身份或重测EXP-2的授权。原型标签限审查文档，LAUNCH_POLICY_VERSION、pi_protocol、固定安装和现场执行均不变。
